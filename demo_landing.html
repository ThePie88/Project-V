Pie Kernel Live Demo

Runtime deterministico per Ivy — prova visiva end-to-end

kernel v0.0.0 · frozen
1

Creazione sessione

Il runner crea una sessione dal seed SEED_V0. Se LMStudio è attivo usa il modello reale, altrimenti FakeLLM deterministico.

2

6 turni con input mirati

Ogni turno attiva un aspetto diverso del kernel: memoria Preference, tool use ALLOWED / DENIED, credenze Belief, recall episodico.

3

Tool sandbox

Turno 3: scrittura file nella sandbox → TOOL_RESULT. Turno 4: lettura path assoluto fuori sandbox → TOOL_DENIED. Il gating CV pre-LLM controlla tool_gate ≥ 0.3.

4

Reward R-STDP

Due segnali di reward +1 inviati inline (dopo turno 2 e dopo turno 5). L'effetto si applica al turno successivo via step 1.5 del runtime loop.

5

Dashboard live

Si apre automaticamente con la sessione pre-selezionata. Mostra: CV channels, spike rate, gating decisions, tool stats, memory counts, budget.

6

Proof folder

Tutti i log vengono copiati in artifacts/demo_<timestamp>/ con un demo_summary.json contenente decision hash, conteggi eventi e metadata del modello.

Cosa cercare nella dashboard

  • Control Vector Channels — 5 linee colorate che evolvono sui 6 turni (memory_gate, cf_k, verbosity_bias, tool_gate, consolidation_urgency)
  • Spike Rate — pattern di firing dei 10 neuroni Izhikevich
  • CV Gating — tabella con ~29 decisioni ALLOW/BLOCK per canale per turno
  • Tool Stats — conteggio chiamate, denied, deny rate %
  • Memory Counts — Preference, Belief, NarrativeMemory per tipo
  • Budget — consumo progressivo su 6 turni, remaining %
  • State — drives (bonding, autonomy, curiosity, safety, competence) + affect
