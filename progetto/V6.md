## Pilastri Research (R1-R5)

### R2 — Readout Trainato (PRIORITA 1)

> Critica: "Non e reservoir computing se il readout e hand-designed."
> Fix: Ridge regression deterministica sul readout layer.

**Implementazione:**

- `pie/state_engine/plugins/readout_training.py` — ReadoutTrainer class
  - Input: reservoir states (128-dim) raccolti durante N turni
  - Target: valori CV desiderati (dalla oracle function)
  - Metodo: Ridge regression (soluzione chiusa: W = Y X^T (X X^T + λI)^{-1})
  - Lambda (regularizzazione) deterministica, seed-controllata
  - Output: `readout_weights.json` con schema_version + seed + dataset_id + hash

- Integrazione nel Reservoir:
  - `Reservoir.train_readout(states, targets, lambda_reg)` — batch training
  - `Reservoir.load_readout(path)` — carica pesi pre-trainati
  - Fallback: se nessun readout trainato, usa hand-designed (backward compatible)

- Training pipeline:
  - Raccolta dati: N turni di exam con engine neural → (reservoir_state, target_CV) pairs
  - Training: ridge regression offline
  - Validazione: held-out split (80/20), metriche per canale
  - Deploy: readout_weights.json caricato al boot

**Definizione Oracle (non ambigua):**

- Funzione pura: `oracle_cv(state, user_input, memory_snapshot) → Dict[str, float]`
  - Deterministica: stesso input = stesso output, nessun RNG
  - Campionamento: **dopo** state.update(), **prima** di gating/decisioning
  - La mappa semantica attuale (hand-designed) e il bootstrap dell'oracle
  - L'oracle puo evolvere (versioned), ma il dataset_id cattura la versione usata

**Dataset e split deterministici:**

- `dataset_id = SHA256(seed || preset || n_episodes || oracle_version || engine_version)`
- Split 80/20: indice deterministico `train_idx = [i for i in range(N) if LCG(seed, i) % 5 != 0]`
  - NO `random.shuffle()`, NO `sklearn.train_test_split()` con random_state
- Normalizzazione feature X: `mean_X`, `std_X` salvati come artifact in `readout_weights.json`
  - Senza questo, i pesi non sono replicabili su un altro dataset

**Metriche held-out per canale (paper-grade):**

- Canali continui (memory_gate, tool_gate, verbosity_bias, consolidation_urgency):
  - **MAE** (Mean Absolute Error)
  - **R²** (coefficient of determination)
  - Pass: R² >= 0.5 e MAE < 0.15 per ciascun canale
- Canale discreto (cf_k, mappato a int):
  - **Accuracy** (exact match dopo round)
  - **MAE** sul valore continuo pre-round
  - Pass: accuracy >= 60%
- "Held-out accuracy" nel senso generico non va: servono queste metriche specifiche

**Pass/Fail:**
- [ ] Ridge regression deterministica: stesso dataset + seed = stessi pesi
- [ ] Held-out: readout trainato >= readout hand-designed su MAE/R² per ogni canale CV
- [ ] Artefatto: `readout_weights.json` con schema_version + seed + dataset_id + hash + mean_X + std_X
- [ ] Backward compatible: senza file readout, usa hand-designed
- [ ] Test determinismo: 3 training runs identici

**Test IDs:**
- `E-RDT-010` — ridge regression deterministic (same seed = same weights)
- `E-RDT-020` — trained readout >= hand-designed on held-out (per-channel MAE/R²)
- `E-RDT-030` — readout_weights.json schema valid (incl. normalization stats)
- `E-RDT-040` — fallback to hand-designed when no trained weights
- `P-RDT-050` — 3 training runs produce identical weights

### R1 — Ablation: Izhikevich vs ODE Lineare (PRIORITA 2)

> Critica: "I neuroni Izhikevich sono decorativi."
> Fix: dimostrare che il blocco spiking processa informazione meglio di un ODE lineare.

**Implementazione:**

- `pie/benchmarks/temporal_tasks.py` — generatori di task temporali:
  - **Delayed XOR**: input binario, output = XOR di input a t e t-delay
  - **NARMA-10**: y(t+1) = 0.3*y(t) + 0.05*y(t)*sum(y(t-i)) + 1.5*u(t-9)*u(t) + 0.1
  - Tutti deterministici con LCG seed (NO `numpy.random`, NO `random`)
  - **Stabilita numerica:**
    - dtype fissato: float64 (Python `float` nativo)
    - arrotondamento: `round(x, 10)` dopo ogni step NARMA per evitare drift
    - clip: NARMA output clipped a [-1e6, 1e6] (safety)
    - burn-in: primi 100 step scartati, poi seq_length step validi
    - NRMSE: `sqrt(MSE) / std(y_target)` — std calcolata su target, non su prediction
    - LCG per generazione u(t): stessa sequenza su Windows/Linux/Mac

- `pie/benchmarks/ablation.py` — AblationRunner class:
  - 3 condizioni:
    1. **Linear ODE**: 10-dim ODE lineare (A*x + B*u), stessa dimensione, niente spike
    2. **Izhikevich only**: 10 neuroni Izh senza reservoir (Tier-1 solo)
    3. **Izhikevich + Reservoir**: sistema completo (Tier-1 + Tier-2 ESN)
  - Metriche per condizione:
    - **Accuracy**: % output corretto (delayed XOR) o NRMSE (NARMA)
    - **Memory capacity**: MC = sum_k (corr(y_k, u(t-k))^2) per k=1..K
    - **Separation ratio**: dist(state_A, state_B) / dist(input_A, input_B)
  - Output: `ablation_report.json` con risultati per task × condizione

- `pie/state_engine/plugins/linear_ode.py` — LinearODEPlugin:
  - Stessa interfaccia StateEnginePlugin
  - A, B matrici deterministiche (LCG seed)
  - Nessuna non-linearita, nessuno spike

**Baseline "fair" (anti-strawman):**

- Linear ODE ha stessa dimensione (10 state vars), stesso input scaling
- **Griglia parametri**: 3 valori di decay rate × 2 valori di input gain = 6 configurazioni
  - Tutte deterministiche, tutte valutate, report mostra la migliore
  - Questo previene l'accusa "hai scelto una baseline debole apposta"
- Il readout della baseline e trainato con la stessa ridge regression (R2)
  - Altrimenti confronti "trained vs untrained", non "nonlinear vs linear"

**Pass/Fail:**
- [ ] Izh+Reservoir > migliore Linear ODE su delayed XOR (accuracy)
- [ ] Izh+Reservoir > migliore Linear ODE su NARMA-10 (NRMSE)
- [ ] Izh only > migliore Linear ODE su almeno 1 task (non-linearita conta)
- [ ] Memory capacity: Reservoir > Izh only > migliore Linear
- [ ] Report artifact: `ablation_report.json` riproducibile
- [ ] Cross-platform: stessi risultati su Windows e Linux (LCG + float64)

**Test IDs:**
- `E-ABL-010` — delayed XOR: Izh+Reservoir > best Linear ODE
- `E-ABL-020` — NARMA-10: Izh+Reservoir > best Linear ODE
- `E-ABL-030` — memory capacity ordering correct
- `E-ABL-040` — separation ratio: reservoir > linear
- `P-ABL-050` — ablation report deterministic (same seed = same results)
- `E-ABL-060` — linear ODE plugin conforms to StateEnginePlugin protocol
- `E-ABL-070` — linear ODE grid search: 6 configs evaluated, best reported

### R4 — R-STDP: Apprendimento con Reward (PRIORITA 4)

> Critica: "STDP non chiude un loop di apprendimento."
> Fix: Reward-Modulated STDP con metrica di performance misurabile.

**Implementazione:**

- `pie/state_engine/plugins/rstdp.py` — RewardSTDPTracker:
  - Estende STDPTracker con segnale di reward
  - `reward(turn, value, source)` — registra reward per il turno
  - Weight update: Δw = η * reward * STDP_trace (eligibility trace)
  - **Reward sources (solo deterministici per training signal):**
    - `tool_success`: tool eseguito senza deny → +1
    - `tool_denied`: deny → -1
    - `recall_hit`: memoria recuperata e usata nel plan → +1
    - `goal_reached`: goal valutato come raggiunto dal kernel → +2
    - `constraint_violated`: vincolo violato → -2
  - **Reward secondario (loggato ma NON usato per training):**
    - `retry_avoided`: LLM output accettato al primo tentativo
    - Motivo: LLM reale non e deterministico → inquina la curva
  - Eligibility trace: decadimento esponenziale per turno

- `pie/benchmarks/learning_curve.py` — LearningCurveRunner:
  - Esegue N episodi (exam scenarios) con 3 condizioni:
    1. **No plasticity**: pesi fissi
    2. **STDP only**: Hebbian senza reward
    3. **R-STDP**: reward-modulated
  - Metriche per episodio:
    - tool_deny_rate
    - recall_precision (definita: recall usato e pertinente / recall totali)
    - mean_cost_per_turn (deterministico: basato su token count)
  - Output: `learning_curve.json` + `learning_curve.png`

**Soglie "significativamente" (non wishful thinking):**

- `tool_deny_rate` ↓ almeno 10% relativo entro 20 episodi (vs no-plasticity baseline)
- OPPURE `recall_precision` ↑ almeno 5% assoluto entro 20 episodi
- OPPURE `mean_cost_per_turn` ↓ almeno 8% entro 20 episodi
- Almeno 1 delle 3 soglie raggiunta = PASS
- Se nessuna raggiunta: R4 = FAIL, non "inconclusive"
- Trend: regressione lineare su metrica vs episodio, slope significativamente != 0 (p < 0.05)

**Pass/Fail:**
- [ ] R-STDP: almeno 1 metrica supera la soglia definita sopra
- [ ] Curva di apprendimento: trend statisticamente significativo (p < 0.05)
- [ ] Ablazione: R-STDP > STDP > no plasticity su almeno 1 metrica
- [ ] Determinismo: stesso seed = stessa curva
- [ ] Reward log append-only in JSONL

**Test IDs:**
- `E-RSTDP-010` — reward signal recorded correctly (deterministici only)
- `E-RSTDP-020` — eligibility trace decays over turns
- `E-RSTDP-030` — weight changes modulated by reward sign
- `P-RSTDP-040` — learning curve reproducible (same seed)

### R5 — Autorita Causale Osservabile (PRIORITA 5)

> Critica: "cf_k cambia ma l'utente non lo vede."
> Fix: CV governa 5 leve percepibili, tracciate nel trace.
> Collega R2/R4 al mondo reale: il controller learned produce comportamento, non solo numeri.

**Implementazione:**

- Estendi ControlVector con 5 leve osservabili mappate a comportamento:
  1. **verbosity_bias** → lunghezza output (terse/normal/verbose)
     - < 0.3: max 1 frase
     - 0.3-0.7: normale
     - > 0.7: elaborato
  2. **tool_gate** → tool policy per turno
     - < 0.3: nessun tool permesso
     - 0.3-0.7: solo tool safe
     - > 0.7: tutti i tool disponibili
  3. **memory_gate** → recall_top_k e tipo
     - < 0.3: k=1, solo episodic
     - 0.3-0.7: k=3, episodic + semantic
     - > 0.7: k=5, full recall
  4. **consolidation_urgency** → scheduling consolidation
     - < 0.3: batch (ogni 5 turni)
     - > 0.7: immediata (ogni turno)
  5. **cf_k** → numero alternative counterfactual (gia implementato)

- Trace eventi: `CV_GATING` event per turno — **contratto, non log libero:**
  - Schema: `{canale: str, valore: float, decisione: str, effetto: str, reason: str}`
  - Invariante: ogni decisione di gating nel runtime ha un CV_GATING corrispondente
  - Nessun gating senza trace, nessun trace senza gating

- Test E2E: stesso input, 3 stati emotivi diversi → output diverso E spiegabile:
  - Stato CALM: verbosity normale, tool tutti, recall k=3
  - Stato ANXIOUS: terse, no tool, recall k=1
  - Stato CURIOUS: verbose, tool tutti, recall k=5

**Pass/Fail:**
- [ ] 3 stati → 3 output diversi con differenze spiegabili dal CV
- [ ] Trace contiene CV_GATING event con catena causale completa (contratto, non free-form)
- [ ] Ogni leva ha effetto misurabile (non solo numerico, ma comportamentale)
- [ ] Invariante: count(CV_GATING) == count(gating decisions) nel runtime

**Test IDs:**
- `E-CVG-010` — CALM state produces expected gating
- `E-CVG-020` — ANXIOUS state restricts tools and recall
- `E-CVG-030` — CURIOUS state expands recall and verbosity
- `I-CVG-040` — CV_GATING event in trace, schema-validated, with full causal chain
- `E-CVG-050` — same input, 3 states, 3 measurably different outputs

Tutti i nuovi artifact prodotti da V6 devono avere schema JSON in `schemas/`:

- `schemas/readout_weights.json` — pesi readout + normalization + dataset_id + hash
- `schemas/ablation_report.json` — risultati per task × condizione × metrica
- `schemas/learning_curve.json` — metriche per episodio × condizione
- `schemas/stability_certificate.json` — (R3b) metodo + dominio + risultato
- `schemas/audit_bundle_manifest.json` — contenuto bundle + hashes
- `schemas/cv_gating_event.json` — schema per CV_GATING trace event

Ogni schema versionato (`schema_version` field). Manifest aggiornato.

## Note sui venue

Il peso relativo dei pilastri cambia in base al target:

| Venue | Core contributions | Supporto |
|-------|-------------------|----------|
| **Paper neuroscienze/ML** | R1, R2, R4 | R3b, R5 |
| **Paper trustworthy/governed AI** | E1, E2, R3, determinismo | R5, E3, E4 |
| **Blog tecnico / HN / Reddit** | R1 (ablation), R5 (demo comportamento), E1 (bundle) | tutto il resto |
| **Enterprise pilot** | E1, E2, E3, E4, E5 | R1-R5 come differenziatori |

- **E1-E5 non sono "nice to have"** se il framing e "governed agents".
  Audit bundle + determinismo + policy versioning sono *core contributions*
  in un paper su trustworthy AI systems. Il venue decide cosa e core.
- **R5 non e solo UX**: dimostra che il controller learned produce
  comportamento osservabile, non solo numeri interni. Collega R2/R4
  al mondo reale.

## Visione

> Un **deterministic reservoir controller** il cui stato interno evolve secondo
> dinamiche spiking **dimostratamente superiori a un ODE lineare** (ablation),
> con readout **trainato** (ridge regression), plasticita **reward-modulated**
> (R-STDP con soglie misurabili), autorita causale **percepibile** (5 leve
> comportamentali tracciate), stabilita **certificata by construction**
> (bounds + empirical verification), e audit trail **forense** (bundle
> deterministico riproducibile).
>
> Non un chatbot con memoria. Non un progetto con claim.
> Un sistema con prove.
