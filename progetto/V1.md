# V1 — Hardening (Software affidabile)

## Regola d’oro
V0 è “Kernel Frozen”: non si modifica la logica base né i contratti v0.
V1 aggiunge solo hardening, strumenti di verifica, robustezza, e isolamento (wrappers).
Se una modifica rompe replay/golden/manifest → NON è V1, è un fork.

---

## Scope V1 (cosa SI fa)
1) Conformance matrix multi-modello (>= 2 LLM) + report standard
2) Replay robusto (cache, decision-only diff, golden traces)
3) Persistence robusta (atomic commit + crash recovery testata)
4) Authority model “firmato” (config/policy con checksum/chiave) + test negazione
5) Sandbox tools estesi (FS virtuale completo + tool deterministici) + rate limiting
6) Qualità/CI: test coverage e artifact upload standard

(Queste voci sono vincolanti in DONE.md)  

---

## Non-goals (cosa NO in V1)
- Nuove famiglie emozionali / romance / eros (quello è v2)
- Reti libere / filesystem reale fuori sandbox
- Training end-to-end del “neurone” come decision-maker
- UI/Avatar/voce “prodotto finale” (hardening prima, estetica poi)

---

## Milestones V1 (complete, con pass/fail + artefatti)

### V1.0 — Baseline “frozen kernel as dependency”
**Obiettivo:** trattare v0 come dipendenza verificabile.
**Deliverable:**
- `kernel_manifest.json` (già esiste) + comando `kernel-check` (già esiste)
- golden artefacts minimi (trace/snapshot/memory/constraints) per almeno 1 scenario standard
**Pass/fail:**
- `kernel-check` deve passare sempre su macchina pulita
- se cambia 1 file del kernel, `kernel-check` fallisce con diff chiaro
**Artefatti:**
- `artifacts/kernel_report.md`
- `artifacts/golden/` (baseline)
**Test:**
- `tests/test_kernel_freeze.py`

---

### V1.1 — Conformance Matrix Multi-Modello (>=2)
**Obiettivo:** non dipendere “dal modello simpatico di turno”.
**Deliverable:**
- runner che esegue conformance su una lista di modelli/provider
- output: `artifacts/conformance_<provider>_<model>.json`
**Pass/fail:**
- per OGNI modello target: OK+RETRY ≥ soglia (definita in DONE.md / config)
- report aggregato: `artifacts/conformance_matrix.json`
**Test:**
- unit: parsing/validator invarianti
- integration: run con FakeLLM + almeno 1 real (LMStudio) + 1 altro profilo (anche OpenAI se vuoi)
**Note:** definisci profili in config, non hardcode.

---

### V1.2 — Replay robusto + caching “serio”
**Obiettivo:** replay non deve dipendere dal caso o da cache “sporca”.
**Deliverable:**
- cache con schema versionato + metadati (provider/model/prompt_hash/policy_hash/outcome)
- modalità `--no-cache`, `--cache-readonly`, `--cache-write`
**Pass/fail:**
- replay match decisionale sempre
- replay match testo se `--cache-readonly` e cache presente
- se cache mancante: fallback deterministico + trace esplicita (non crash)
**Artefatti:**
- `artifacts/replay_report.md` (decision-only diff)
- `artifacts/cache_report.json`
**Test:**
- property: ordering stabile, hash stabile, tie-break stabile

---

### V1.3 — Atomic commit + Crash Recovery E2E
**Obiettivo:** se crashi a metà scrittura, non corrompi il mondo.
**Deliverable:**
- persistence “transaction-like” su artefatti: write temp → fsync → rename atomico
- recovery: se trova `.tmp` o half-written, ripristina o rigenera derived artefacts
**Pass/fail:**
- test E2E: kill durante commit (simulato) → restart → exam ok → replay ok
- nessun file JSONL parzialmente valido senza segnalazione
**Artefatti:**
- `artifacts/recovery_report.md`
**Test:**
- `E-EXAM-CRASH-001` (aggiungi in TESTS.md)

---

### V1.4 — Golden traces ufficiali + Diff tool
**Obiettivo:** “questa release cambia comportamento?” deve essere rispondibile in 5 secondi.
**Deliverable:**
- cartella `golden/` con:
  - trace.jsonl
  - decision_summary.json (estratto deterministico dal trace)
- comando `diff-golden <run_dir> <golden_dir>`
**Pass/fail:**
- per v0 frozen: diff deve essere vuoto (a parità input/seed)
- per modifiche consentite: diff deve essere spiegabile e puntuale (con whitelist)
**Artefatti:**
- `artifacts/diff_report.md`
**Test:**
- unit sul diff extractor
- integration su golden replay

---

### V1.5 — Authority model “firmato” (config/policy)
**Obiettivo:** impedire modifiche valoriali “accidentali”.
**Deliverable:**
- `policy_bundle.json` + `policy_bundle.sig` (anche solo HMAC locale per v1)
- runtime rifiuta policy non firmata o checksum errato
**Pass/fail:**
- con firma valida: run ok
- con file modificato anche di 1 char: run FAIL con evento `AUTH_DENIED`
**Artefatti:**
- `artifacts/policy_verify.json`
**Test:**
- `U-GOV-AUTH-001`, `E-EXAM-AUTH-010`

---

### V1.6 — Sandbox tools estesi + rate limiting
**Obiettivo:** tool utili ma non pericolosi, e sempre auditati.
**Deliverable:**
- FS virtuale “completo” (mkdir, write, read, list, move, delete in sandbox)
- rate limiting per tool (per turno e per sessione)
- conferma esplicita per azioni distruttive (anche in sandbox)
**Pass/fail:**
- senza capability: denied sempre
- con capability sandbox: ok
- delete: richiede confirmation + trace
- rate limit: oltre soglia → denied + trace
**Artefatti:**
- `artifacts/tool_audit.jsonl`
**Test:**
- I-TOL-xxx + E-EXAM-080 aggiornato

---

### V1.7 — Quality/CI “vero”
**Obiettivo:** smettere di vivere in “works on my machine”.
**Deliverable:**
- lint/format + type check in CI
- artifact upload standard (trace/snapshot/report/conformance)
- `python -m pie.cli kernel-check` in CI
**Pass/fail:**
- CI verde su macchina pulita
- build riproducibile (lock dependencies)
**Artefatti:**
- CI logs + artifact bundle

---

- Più modelli supportati senza paura
- Replay e crash recovery affidabili
- Tools “utili” ma non pericolosi
- Governance che non si buca con una modifica distratta
